# Решения по воронке демо v2 (Elke EN)

База: задача `cursor-task-new-demo-funnel.md`, код на `b4f96b0` и последующий `b4f96b0` (возвраты). Новые записи в v2 не включаются, пока не будет отдельного «да» на выкладку. По умолчанию флаг остаётся `v1`.

## Уже решено

Письма демо-воронки дают **одно предложение: 40%**, код **SPECWWM4**. В Tilda этот код уже настроен на 40%. В черновиках писем v1 скидка уже написана как 40% и код берётся из `sale_coupon_code` (по умолчанию SPECWWM4). Отдельную цену $59.40 в кабинет не зашиваем: сумму применяет Tilda по коду.

По процессу больше ничего не меняется. Не трогаем:

- адрес и имя отправителя (`robot@worldwatercolormasters.art`, имя из текущего конфига);
- привязку оплаты к ученику (как сейчас, по email в вебхуке Tilda);
- уведомления сотрудникам (как сейчас, без ежедневной сводки);
- общие правила записи, паузы и снятия прогона;
- показ цены, таймера и баннера предложения внутри уроков.

Меняются только три вещи, и только как в задаче:

1. Само предложение в письмах: 40% и SPECWWM4.
2. Набор писем v2 (новые id с префиксом `v2_`, чтобы правки старых шаблонов в админке их не перекрыли).
3. Тайминги v2 из таблицы задачи (после первого просмотра, 24 ч без просмотра, письма ценности, финал, повторное открытие демо). Шесть писем раз в 12 дней убраны: после письма о повторном демо процесс заканчивается.

Пока в тексте письма остаётся незаполненный плейсхолдер `[[...]]`, такое письмо не отправляется.

## Что уже проверено в коде

- `EmailTemplateRenderer::render()` берёт строку из `email_templates`, и только если её нет — черновик из кода.
- Локальная база (`scripts/report-email-template-overrides.php`): у `demo`, `reminder_demo_no_login`, `reminder_demo_expiring`, `sale_demo_discount_24h`, `sale_demo_discount_3h` своих строк нет, идут черновики. На проде это нужно посмотреть отдельно: строка в админке перекрывает код.
- Ссылка на оплату сейчас: лендинг с `promo=SPECWWM4` и `utm_source=email`. Страница сама код в корзину не подставляет.
- Вебхук Tilda ищет ученика по email. Телефон в разбор платежа не входит. Свои UTM читаются, если Tilda прислала их в теле, cookie или адресе страницы.
- Письмо `demo` сейчас в списке маркетинговых (`MarketingEmailDelivery`): уходит с `Precedence: bulk` и List-Unsubscribe.
- `coupon_expires_label` для финала v1 считается как «сейчас + 24 часа», а не из срока прогона.
- Выключение процесса — пауза: люди остаются на текущем шаге. Это не сброс.

## Цена в ссылке корзины

Если позже появится ссылка вида `#order:...=цена`, цену задаёт браузер. Это слабое место: позицию можно открыть по этой цене без проверки срока. Пока оплата идёт через уже настроенный SPECWWM4, кабинет свою цену в корзину не подставляет. Срок кода на стороне Tilda кабинет не проверяет.
